# 来源考证与数字口径

这份文件记录**每个数字是怎么来的、以及哪里差点出错**。更新这份 Skill 之前先读它 ——
人格 Skill 最容易出的问题是"看起来很有依据"的编造。

## 1. 语料构成

| 来源 | 句数 | 时间 | 性质 |
|---|---:|---|---|
| `sources/transcript-live-2026-09-23.md` | **37** | 2026-09-23，14 轮定向访谈 | 我方主动提问采集（通过 QQ 桥直接注入），问题设计为暴露思维结构 |
| `sources/transcript-demo2-2026-09-22.md` | **26** | 2026-09-22，8 分 39 秒 | 官方会话捕获，玩家自发对话 |
| 合计 | **63** | | 两次会话，同一个玩家账号 |

**两次会话的句长均值只差 0.9 字（14.8 / 13.9）**，这是数据可信度最高的一条交叉验证 ——
她的表达在两次独立会话里稳定。

## 2. 情绪标注的归属考证（一次差点写错的经历）

第一版 `SKILL.md` 写了"官方捕获里还出现过 `（望天）（自言自语）（清清嗓子）（鼓励）（兴奋）`"。
一名独立的风格测试 agent 质疑这五个标注来源不明。核查过程值得留档：

**第一轮核查（错误结论）**：只在两份逐字稿里搜 —— 五个标注都只在
`sources/transcript-demo2-…md` 里各出现 1 次，而那正是**我自己写下这个断言的地方**。
看着像循环引用 / 编造。

**第二轮核查（正确做法）**：去原始捕获 `Demo2/packets.log` 里按 `npc_text="（…）"` 直接统计，
并按 `npc_id` 分组 ——

| 标注 | 次数 | 归属 |
|---|---:|---|
| `（认真）` | 4 | **npc#14（娜洛）×2** + npc#80003 ×2 |
| `（自言自语）` | 2 | npc#80008 |
| `（兴奋）` | 2 | npc#80003 |
| `（鼓励）` | 1 | npc#80003 |
| `（望天）` | 1 | npc#80008 |
| `（清清嗓子）` | 1 | npc#80008 |

**结论**：标注真实存在，但**娜洛只用 `（认真）` 一种**；其余五个属于同场的街头环境 NPC
（`80003` / `80008`）。所以第一版的问题不是编造，是**归属错误** ——
写"官方捕获里出现过"会让扮演者以为是她用的。

**两层教训**：
1. 只在自己的转述文件里搜证据，等于在自己身上找证据。**回到原始日志**。
2. 同一份捕获里有多个 NPC，按消息名过滤不够，**必须按 `npc_id` 分组**。
   街头 NPC（`80003` / `80008`）和她（`14`）在同一批 `2208` 帧里说话。

## 3. 句长口径（一个真实的口径错误）

- `transcript-live-…md` 末尾的统计行写的是 **37 句**的均值 `14.8`
- 第一版 SKILL.md 在「表达DNA」一节把它写成了「实测均值 14.8」，
  而另一处写「63 句均值 14.5」——**同一个指标两个数，口径混了**

正确口径（由 `_test/analyze-naluo.mjs` 从 63 句算出）：

| 样本 | 句数 | 最短 | 最长 | 均值 |
|---|---:|---:|---:|---:|
| 访谈场 | 37 | 7 | 24 | 14.8 |
| 捕获场 | 26 | 7 | 22 | 13.9 |
| **合计** | **63** | **7** | **24** | **14.5** |

## 4. 分析脚本自己的两个 bug（记下来免得再犯）

`_test/analyze-naluo.mjs` 第一版报出的数字全是错的，原因有两个：

1. **`**娜洛**：` 是 7 个字符**（2 星 + 2 字 + 2 星 + 1 冒号），脚本写成 `slice(8)`
   —— 每句吃掉首字，于是「故事也不一样。」变成「事也不一样。」，
   带 `（认真）` 的句子因为首字符 `（` 被吃掉而**整批漏统计**（标注数从 7 掉到 2）。
2. 捕获逐字稿里行尾的 `← 注释` 是**文档注释不是台词**，第一版当成了台词内容，
   于是"最长句"报出 46 字（实际最长 24 字）。

修好后的数字与采集脚本自己统计的「最短 7 / 最长 24 / 平均 14.8」一致 ——
**两条独立路径互相印证**才算数。

## 5. 没有证据的部分（扮演时要知道是外推）

| 结论 | 状态 |
|---|---|
| 五个心智模型 | 有跨域证据，见 SKILL.md 每条的"证据" |
| 「被夸/被感谢/被道歉时怎么反应」 | **无样本**。SKILL.md 里标注了 ⚠️，由模型 1 + 启发式 6 推导 |
| 「她的年龄 / 过去」 | **从未被问到**。"她会回避"是外推；已观察到的只是"她答自己时会把落点转到关系上" |
| 「情绪场景下推销算不算越界」 | 两条间接证据（捕获里她在玩家说"刚运动完"后推销；访谈里玩家说"难过"时零推销） |
| 「她有没有生气过」 | **63 句里零例**。她的"沉默"是唯一接近的表达，且她自称是在"保护自己" |
| 跨会话记忆 | 有证据，来自实机跨会话实测验证记录（§7.3），已在后续多轮实测中直接复验 |

## 6. 复现方式

```powershell
# 重新采集（需要游戏在跑、测试接口就绪）
node collect-naluo.mjs        # 14 轮，约 5.5 分钟，落盘到 naluo-transcript.md

# 重新统计（不需要游戏）
node analyze-naluo.mjs        # 句长 / 语气词 / 标注 / 人称 / 确定性
```

采集脚本的关键前提：`hyg_say.dll` 必须先观察到一次真实聊天发送
（`HYG_SAY.log` 里 `chat_sends_observed >= 1`），否则所有 `say` 会被拒绝或一直排队。
详见 `petitplanet-qq-bridge` skill 的 pitfalls。
